# Contextual POPS executable extraction

`ingest/src/pops.zig` accepts borrowed DATA.PSP and DATA.BIN bytes, recovers a
title key from the PS1 DATA.BIN PGD, and returns owned authenticated DATA.PSP
plaintext. It writes no files, keys or reports and launches no subprocess.
The returned bytes must be gzip or ELF. Decoded ELF objects use `.elf` even
when their ELF type is PSP PRX (0xffa0). Gzip naming preserves the format
detected after decompression: `DATA.PSP → DATA.gz → DATA.elf`.
The PRX subtype remains in the ELF header; no conversion occurs.

The normal Zig build links the pinned pspdecrypt backend already used by PRX,
plus libkirk's authenticated PGD key-recovery routines. No separate installation
or `PSPDB_POPS` override is used. Source:
https://github.com/John-K/pspdecrypt at `c156627db7634d395c380c0a9589130f603307fc`.
The narrow POPS tag/key/XOR recipe is available only to seeded type-5 decoding;
standalone PRX coverage is unchanged. Mutable KIRK and BBMac workspace is
thread-local. Zig-PSP continues to own PBP parsing.

## Supported profile and checks

Initial support is POPS_EXEC mode20, tag0DAA06F0, KIRK code0x65, PGD key index1 /
DRM type1. Other profiles fail explicitly. PSISOIMG0000 locates PGD at0x400;
PSTITLEIMG0000 locates it at0x200; real multi-disc remains unverified. The decoder
checks section/header bounds, declared PRX/ciphertext sizes and the DNAS MAC;
pspdecrypt then checks header SHA1 and KIRK authenticates the ciphertext.

The native cutover reproduces Ginsei's 7134-byte gzip payload exactly against
the retained helper oracle. Earlier helper research verified gzip and raw ELF
variants; this is historical coverage, not a new native multi-title claim.

## Catalog attachment

PBP revision 2 is the extraction/cache unit. Its DATA.PSP file entry carries an optional
`extraction` object containing the encrypted source's exact hash/size, native
POPS provenance and immediate decoded entries. The contextual result is scoped
to that PBP occurrence; it is not a globally registered PRX tree or a fake file.
The decoder borrows both sections from the enclosing PBP, while the attachment
target remains DATA.PSP. Generated bytes retain normal content hashes.

The website accepts the inline tree only when its source hash/size matches the
file entry. Generic gzip/ELF processing continues below it. Catalog validation,
download indexing, dependency freshness and cached-task reuse traverse the
inline children. POPS and PBP revision 2 invalidate affected older results;
the PBP revision changes because it owns the inline provenance bytes.
Do not reuse an old extractor revision after changing output behavior: historical
catalog results remain immutable.
